Method note and data issues

28,258 records were read from the semicolon-delimited export; none were excluded and none were dropped. The LLM Reasoning column was treated as the description field throughout. Every status value in the export matched an expected value, so the «Unknown / blank» row is zero in every table; 0 records could not be classified.

4,540 records (16.1%) have a blank description and 6,998 (24.8%) carry a description saying the page could not be read, leaving 16,720 usable descriptions (59.2%) — the second denominator of Table 3. Those two populations cannot carry evidence, so any indicator test applied to them would return a false negative by construction, not a finding.

A record can show more than one unreadable signal, so these rows sum to more than 6,998.

The weak-only spillover is 719 records (2.5%): sites whose description proves they are Hispanophone gambling sites but carries nothing that ties them to Chile. Counting them as Chile-relevant would inflate the qualifying subset from 277 to 996 and pull in Peruvian, Argentine, Mexican, Colombian and Spanish estates — the regional contamination risk this report is designed to keep out.

Data issues found.

  • Ambiguous indicator tokens. Several STRONG indicators are also ordinary English words or common acronyms: Enjoy, Dreams, MACH, Chek, Tenpo, SII, BCI, SCJ. Matched as bare words they produced 30 spurious hits on phrases such as «enjoy the best online gaming experience with 1xBet Morocco». They are therefore matched only in brand or contextual form — Casino Enjoy, Enjoy Casino, Enjoy Chile, Casino Dreams, and the acronyms only alongside a Chilean context term. This is a matching decision, not an inference, and it is reversible.
  • Unreachable-page detection by HTTP code. Matching any three-digit 4xx/5xx number produced 361 false hits on prize and jackpot amounts (for example «R$ 206.738.555,12»). Codes are therefore counted only alongside error phrasing.
  • Mixed granularity in the hostname field. The export mixes bare registrable domains, subdomains and hostnames carrying operational labels; axis B tokenises the hostname on dots, hyphens and underscores so that example-cl.net and chile.example.com both match, while .cl domains are handled by axis A alone.
  • No record identifier column. The export carries no stable record ID, so records are identified here by their CSV line number (L2 is the first data row).

Settings. The prompt's defaults were applied without change, as no confirmation was available at run time: Table 4 «overall» is the union of the four axes; .gob.cl and .gov.cl are counted and reported separately; weak indicators never qualify alone; axis D is included; and the unit of count is one record per row, not one row per registrable domain.
