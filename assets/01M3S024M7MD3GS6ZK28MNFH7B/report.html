Method note and data issues

  • Total records read: 40,975, parsed from dataset.csv as semicolon-delimited CSV with quoted fields. No rows were excluded, and no row failed to classify, so no record IDs are listed as unclassifiable.
  • The manifest reports 40,981 rows; this report counts 40,975. The file holds 40,982 physical lines (40,981 after the header), but one record — ki8.fun — contains six newline characters inside a quoted LLM Reasoning value. The exporter counted lines; 40,975 is the correct count of logical records. Nothing is missing from the data.
  • The description field was LLM Reasoning, the only free-text reasoning column in the export. Available columns: Domain, URL, Status, Source, Rank, Updated at, Confidence, LLM Reasoning, Case Management Status.
  • All status values matched an expected value. Four distinct values occur — Illegal gambling, Review needed, Not gambling, Unreachable. No status was blank, unrecognised or otherwise unmatched, so the “Unknown / blank” row is empty in every table and has been omitted rather than shown as zero.
  • Settings applied were the prompt defaults, as the request supplied no overrides: union for the Table 4 overall figure, no excluded TLDs (.go.th, .ac.th and .mi.th counted), and one record per row with no de-duplication to registrable domain. The request carried an empty query and a null date range, so the export was used in full as delivered.
  • Percentages are rounded to one decimal place and a column of rounded components may therefore differ from its rounded total by up to 0.1 points.
