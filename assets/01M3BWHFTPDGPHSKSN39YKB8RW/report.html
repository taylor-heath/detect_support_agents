Method note and data issues

23,943 records were read from the semicolon-delimited export; no rows were excluded and none were dropped. The LLM Reasoning column was treated as the description field, and the Table 3 test was applied to that column alone. Every status value in the export matched an expected value, so the «Unknown / blank» row is zero in every table, and 0 records could not be classified. Two of the five expected status values, Licensed gambling and Unreachable, do not occur in this export and are shown as zero rather than omitted.

3,615 records (15.1%) carry a blank description. They cannot satisfy the Table 3 test by construction, so the Thai-indicator subset is a floor rather than a measurement.

Data issues found.

  • Record identifiers. The export carries no stable record ID column, so records are identified here by CSV line number, where L2 is the first data row.
  • Ambiguous indicator tokens. «LINE» is a common English word, so the contact-convention test matches only the explicit forms LINE ID, LINE app, LINE official, LINE@ and the Thai ไลน์, never the bare word. Bank acronyms are matched case-sensitively on a token boundary for the same reason.
  • The two tests measure different things. Only 7 records satisfy both the domain test and the description test, so the .th subset and the Thai-indicator subset are close to disjoint. A figure quoting either one alone understates Thailand relevance.
  • Physical lines versus records. The export manifest reports 23,949 rows against the 23,950 physical lines of the file; 23,943 records parse once quoted fields carrying embedded line breaks are joined. The difference is a line count, not missing data.

Settings. The prompt's defaults were applied without change, as no confirmation was available at run time: the Table 4 overall figure is the union of the two tests; no top level domains are excluded, so .go.th, .ac.th and .mi.th are counted; and the unit of count is one record per row, not one row per registrable domain.
